## Findings

### PY-01 — The two most-used DB writers commit by default, inverting the house rule
**Severity:** Critical · **Category:** rule-violation + safety
**Location:** `supabase/admin/lesson_aggregate.py:1751`; `supabase/admin/interaction_reports.py:316`. Rule stated in `CORE.md:335-337`, `AGENTS.md:77-78`, `.ai/patterns/python.md:268` and checklist line 408.
**What:** Both use `if args.dry_run: rollback else: commit`. `--dry-run` is the opt-in; every other
script in the repo requires `--commit` to write. The skill doc's own usage example shows `--dry-run`
then the bare command as the "now commit" step.
**Why it matters:** A copy-paste that loses its trailing flag publishes AI cohort prose to the live
rollup with no review. These are the two commands an operator actually runs.
**Confidence:** Confirmed
**Fix:** Rename to `--commit` (invert the check) in both; update SKILL.md examples.
**Live-system risk:** Inverting mid-semester breaks muscle memory and any scheduled invocation — do it
between terms, or document an explicit carve-out until then.
*(Corroborated independently as OPS-06.)*

### PY-02 — `build_110_preflights.py` hardcodes another person's macOS home directory
**Severity:** Critical · **Category:** portability
**Location:** `scripts/fall2026/build_110_preflights.py:40-41`
**What:** Hardcodes `/Users/caseypellizzari/...` with **no config fallback** — unlike its sibling
`build_fall_preflights.py`, which correctly reads `textbook_base_path` from config.
**Why it matters:** Breaks for anyone but that one person, on any Windows machine including the
course director's. This is the Physics 110 term builder.
**Confidence:** Confirmed
**Fix:** Read `textbook_base_path` from config exactly as the 215 builder does.
**Live-system risk:** None to fix — the script is dry-run by default.

### PY-03 — Three actively-used `scripts/` files import an undeclared third-party package
**Severity:** Critical · **Category:** rule-violation
**Location:** `build_fall_preflights.py`, `build_110_preflights.py`, `extract_preflight_figures.py` — all `from docx import Document`
**What:** `python-docx` is not stdlib, is **not in `requirements.txt`**, and has no `docs/decisions/`
entry. This directly violates the "`scripts/` is stdlib-only" rule stated in CORE.md §2, PROJECT.md,
and `.ai/patterns/python.md`.
**Why it matters:** A new operator following the documented setup (`pip install -r requirements.txt`)
gets an `ImportError` on the term builders with no indication what to install. Recently touched
(2026-08-06), so these are live tooling, not history.
**Confidence:** Confirmed
**Fix:** Either declare `python-docx` in `requirements.txt` and move these three to the admin tier, or
record the exception explicitly. Silence is the worst of the three options.
**Live-system risk:** None to fix.

### PY-04 — Hardcoded foreign absolute path in a test's `sys.path`
**Severity:** High *(see note)* · **Category:** portability
**Location:** `supabase/admin/aggregate_summarize_test.py:11`
**What:** `sys.path.insert(0, r"c:\...\Socratic Instruction\Core_Preflights\supabase\admin")` — wrong
drive, wrong project name, does not exist on this machine.
**Confidence:** Confirmed the code.
**⚠ Disagreement with the docs/tests audit (TEST-05), which rated this Low** after confirming via
`run.mjs`'s invocation pattern that Python's default `sys.path[0]` fallback still resolves the import.
**Resolution: treat as Low-Medium** — currently harmless, misleading dead code, breaks under `-m` or a
future test runner.
**Fix:** `Path(__file__).resolve().parent`, matching its siblings. **Live-system risk:** None.

### PY-05 — `connect()` reimplemented five times, already diverged
**Severity:** High · **Category:** duplication
**Location:** canonical `supabase/admin/app_tier_check.py`; reimplemented in `set_due_time.py`, `port_sandbox_due_dates.py`, `isolate_offering_content.py`, `split_training_offering.py`
**What:** All four reimplement `connect()` **despite already importing `read_env` from that same
module**. `split_training_offering.py`'s copy has no `.get()` defaults for `PREP_DB_PORT` /
`PREP_DB_NAME` and will `KeyError` where its siblings default to `"5432"` / `"postgres"`.
**Confidence:** Confirmed
**Fix:** Shared `db_common.py`. **Live-system risk:** Low.

### PY-06 — `read_env()` copy-pasted three times
**Severity:** Medium · **Category:** duplication
**Location:** `app_tier_check.py`, `create_course_offering.py`, `gen_db_schema.py`
**What:** Both copies' own comments say "mirrors app_tier_check.py" — the reuse was seen and skipped.
**Confidence:** Confirmed · **Fix:** Fold into `db_common.py` with PY-05.

### PY-07 — The Windows UTF-8 console workaround appears ~13 times in 5 styles
**Severity:** Medium · **Category:** duplication + error-handling
**Location:** across `scripts/` and `supabase/admin/`; unsafe variant in `lesson_aggregate.py`, `interaction_reports.py`, `seed_training_lessons_03_04.py`
**What:** Three files use `sys.stdout = TextIOWrapper(...)` **reassignment**, which
`grade_interactive.py`'s own in-repo comment explains can cause "I/O operation on closed file" if two
modules both do it in one process.
**Why it matters:** Not live today, but the unsafe pattern persists in 3 files *after* being
identified and fixed in a 4th. **The one consolidation backed by a documented real bug.**
**Confidence:** Confirmed · **Fix:** One `ensure_utf8_console()` helper.

### PY-08 — Four scripts load `config.json` at import time
**Severity:** Medium · **Category:** rule-violation
**Location:** `export_poc_snapshot.py`, `clean_poc.py`, `clean_stale_phys110_ids.py`, `seed_training_preflight02.py`
**What:** Contradicts the explicit "no import-time side effects" rule — and contradicts a sibling
script's own docstring (`zero_non_submitters.py`) explaining exactly why not to.
**Confidence:** Confirmed · **Fix:** Move to call time; resolved for free by the shared REST helper below.

### PY-09 — The two course builders are ~40% copy-paste with one silent divergence
**Severity:** Medium · **Category:** duplication
**Location:** `build_fall_preflights.py` vs `build_110_preflights.py`
**What:** ~130-150 of ~330 lines each are near-identical (`upsert()`, `main()`, Q-text constants,
`norm()`). **The real divergence:** 215's `due_utc()` subtracts a day (lesson-date schedule); 110's
does not (already-due-date schedule). **Correct today** — but a trap if either function is ever copied
into the other's context.
**Confidence:** Confirmed
**Fix:** Shared `_preflight_builder_common.py`, which forces the `due_utc()` divergence to be visible
from both files rather than discoverable only by diffing.

  loopback safety.
