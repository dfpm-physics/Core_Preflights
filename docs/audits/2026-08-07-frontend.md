# PREP — Frontend Architecture & Code-Quality Review
*Static analysis only. No DB connection, no script execution, no repo writes.*
*Excluded (in-flight artifact library): `site/faculty/artifacts.html`, `site/js/faculty-artifacts.js`, `scripts/artifacts/**`, `_builder/**`, `tests/browser/test-artifacts.html`. Nothing below depends on them.*

**Counts:** 16 findings — Critical 1 · High 4 · Medium 4 · Low 7

**Headline:** unusually well-maintained for a codebase with no build step. Zero loose equality, one
`esc()`, 3 `!important`, 8 duplicated CSS selectors out of 1033, a real linker test that parses inline
page modules, and rationale comments frequently better than the code they sit above. Problems
concentrate in four places: **one genuinely diverged constant** the migration that changed it did not
know existed; **42% of hand-written JS living inline in HTML**; **a faculty data layer that never
coalesced**; and **~55 Supabase calls that discard `error`**.

## Findings

### FE-01 — The effort→points curve has a seventh copy, and it is the diverged one
**Severity:** Critical · **Category:** duplication / correctness
**Location:** `site/student/interaction-submit.html:62-67` (canonical: `supabase/migrations/app/019_effort_partial_credit_flat.sql:72-76`; agreeing copies: `site/js/schema.js:697`, `site/js/faculty-rollup.js:582`, `supabase/admin/interaction_reports.py:103`, `supabase/admin/lesson_aggregate.py:213`)

**What:** Migration 019 (2026-07-30) changed partial credit from `points_possible / 2` to flat
`LEAST(1, points_possible)`. Its header names **six copies that must agree**; all six were updated.
`interaction-submit.html` carries a **seventh**, not on that list, not updated:
```js
function effortPoints(e, possible) {   // mirrors app.grades_points_from_effort()
  if (e == null) return 0;
  if (e >= 3) return possible;
  if (e >= 1) return Math.round((possible / 2) * 100) / 100;   // ← the retired rule
  return 0;
}
```
Its output is shown to the student on the success screen (`:293-295`): *"Your instructor will see an
effort rating of 2/5 (about **1.5** of 3 pts)."* The trigger writes **1**.

**Why it matters:** On the only value that exists today — a 2-point offering — `2/2 == min(1,2) == 1`,
so the rules are indistinguishable and this is invisible. That is precisely the condition migration
019 documents as why the divergence went unnoticed for months. The two phys-310 lessons are
`points_possible = 3.00`; the migration notes neither has a graded interactive activity *yet*. The
first time one does, a cadet is told 1.5 and graded 1 — on the submission-confirmation screen, the
worst place to misquote a score, and the instructor never sees what the student was told.

**Confidence:** Confirmed (both code paths read; migration's own inventory read; arithmetic checked at pp = 1, 2, 3).

**Fix:** Delete `effortPoints` and import `pointsFromEffort` from `../js/schema.js` — the page already
imports `questionsOf, answeredCount` from that module at `:41`, so this is one identifier added and
one function deleted. Register the page in the 019 header and CORE.md §6. Better still: have
`faculty-rollup.js:582` import it too, taking the frontend to **one** copy.

**Live-system risk:** Two-minute swap, safe. Touches a **student-facing page behind a frozen contract
URL** — the file keeps its path and its `#t=/#i=/#r=/#d=` hash handling, neither of which this goes
near. Edit is confined to a display string. Verify via `python -m http.server 8000` with a hand-built
hash payload; `test-imports.mjs` catches a mistyped import.

### FE-02 — ~55 Supabase calls discard `error`, so an outage renders an empty page
**Severity:** High · **Category:** correctness
**Location:** 55 of 120 `await db.from(...)` sites. Worst: `js/student-data.js:73-77, 87-91, 397-401`; `js/faculty-data.js:140-151, 262, 301, 306, 314, 336`; `js/faculty-rollup.js:116, 316, 932, 940`

**What:** The dominant idiom is `const { data } = await db.from(...)`, `error` never destructured,
followed by `data || []`. supabase-js **returns** `{data, error}`; it does not throw. An RLS refusal,
network drop, paused free-tier project, or renamed column all produce `data === null` → `[]` → a
successfully-rendered empty list.

`student-data.js:80` is sharpest:
```js
const offerings = shapeOfferings(offeringRows, ctx);
if (!offerings.length) return [];          // indistinguishable from "the query failed"
```
A cadet whose query failed sees the same dashboard as a cadet with nothing assigned.

**Why it matters:** `util.js` contains `showFatal`/`runPage` written *specifically* so "a page that
fails should say so" — but `runPage` only catches **thrown** errors, and this data layer never throws.
The guard and the data layer pass each other by. The Supabase project **pauses after ~1 week idle**
(CORE.md §1), so the most likely real failure is exactly the one that renders as "you have no
assignments." The counter-pattern already exists in-repo: `report.html:231-244` catches, sets
`reportLoadError`, and its comment explains it was added because a `ReferenceError` looked like a hung
computation for a day. That lesson was never generalized.

**Confidence:** Confirmed (idiom counted mechanically; three call chains traced end to end).

**Fix:** One helper in `js/supabase.js`:
```js
export async function must(q, what) {
  const { data, error } = await q;
  if (error) throw new Error(`${what}: ${error.message}`);
  return data;
}
```
Convert in dependency order, `student-data.js` first (one file, four queries, covers every student
surface). `runPage`/`showFatal` then does the rest with no page changes. Panels that must degrade
rather than fail — dashboard tasks and EI, already `.catch(() => [])` — keep their own catch.

**Live-system risk:** Behaviour-changing; not a drop-in mid-lesson. Ship the student loader alone
first and watch one deadline cycle. Do it between day tracks, not between an M-day deadline and its T-day.

### FE-03 — Four pages have no entry-point error guard; two of them matter
**Severity:** High · **Category:** correctness
**Location:** `site/faculty/report.html:127` (`else { init(); }`), `site/student/interaction-submit.html:110` (`if (ctx) init();`), `site/faculty/help.html:26`, `site/student/help.html` — 15 of 19 pages correctly use `runPage(ctx, init)`

**What:** `init()` is `async` on all four; the returned promise is dropped with no `.catch`. Any throw
before first render leaves the page on its `.center-load` spinner with the cause only in a console
nobody has open.

`report.html` is the worst placement: 1567 lines, largest faculty page, ten internal `catch` blocks
(the author clearly cares) — but the outermost frame `init() → start()` is unguarded, and `start()` is
where `loadManager(ctx)` is awaited. `interaction-submit.html` is second worst: student-facing, and it
is where a cadet lands *after finishing an interactive lesson*, carrying the only copy of their report
in a URL hash. Silent failure there reads as "my work vanished."

**Confidence:** Confirmed (all 19 page entry points audited).
**Fix:** `runPage(ctx, init)` in place of the bare call. `report.html` and `interaction-submit.html`
already import from `util.js` — one added identifier each. The two `help.html` pages are three lines each.
**Live-system risk:** Two-minute swap, no behaviour change on the success path. `interaction-submit.html`
is a **frozen contract URL**; this does not move it or touch the hash contract.

### FE-04 — 42% of hand-written JavaScript lives inline in HTML
**Severity:** High · **Category:** layering

| Page | total | inline JS | its module | ratio |
|---|---|---|---|---|
| `faculty/admin.html` | 2033 | **1908** | `faculty-admin.js` 463 | 4.1 : 1 |
| `faculty/lessons.html` | 1902 | **1617** | `faculty-lessons.js` 1079 | 1.5 : 1 |
| `faculty/report.html` | 1567 | **1474** | `faculty-rollup.js` 966 | 1.5 : 1 |
| `faculty/grade.html` | 731 | 634 | `faculty-grade.js` 854 | 0.7 : 1 |
| `faculty/student.html` | 709 | 629 | `faculty-student.js` 349 | 1.8 : 1 |
| `faculty/system.html` | 612 | 558 | `system-admin.js` 370 | 1.5 : 1 |
| **all pages** | 10 625 | **9 293** | modules 12 945 (ex-generated) | **42% of hand-written JS** |

**What:** `admin.html` carries 1908 lines of inline module script — roster rendering, CSV drop-zone,
provisioning, staff coverage drag-and-drop, section editor, extensions report, export — while
`faculty-admin.js` holds 463 lines of loaders. The renderers never made it out.

**Why it matters — three losses, not one:**
1. **Reuse.** The two EI-modal copies (FE-06) and two `openModal` copies exist *because* they are
   inline. Nothing inline can be imported.
2. **Cacheability.** A module caches across pages; inline script re-downloads every navigation.
   `admin.html` is 123 KB of which ~113 KB is script that can never be cached separately.
3. **Testability.** `tests/app-schema/` has 28 test files importing modules directly. They cannot
   reach inline code. `test-imports.mjs` extracts and *parses* inline blocks — a real safety net — but
   parsing is not testing, and the CHANGELOG records a template-literal bug in `admin.html` that
   reached production because nothing but a hand-run parse covered it.

This is **not** a "should be bundled" finding. Extraction needs no build step: move a function into
`js/faculty-admin.js`, `export` it, `import` it.

**Confidence:** Confirmed (counted mechanically per `<script>`/`<style>` block).
**Fix:** Extract **pure functions first** — those taking data and returning an HTML string or
decision, no `document` access. In `admin.html` that is most of the roster/preview/coverage rendering.
Each becomes testable in the existing harness the day it moves. Leave the wiring inline. Target: no
page over ~400 lines of inline script.
**Live-system risk:** Incremental and individually reversible, but the largest diff here and it
touches director-facing pages mid-term. One function at a time, out of term if possible. No frozen URL affected.

### FE-07 — Four vocabularies for "which sections am I looking at"
**Severity:** Medium · **Category:** duplication / UX consistency
**Location:** `grade.html:171-172` (`''` = "— all my sections —", `'__all__'` = "All sections (entire course)"); `gradebook.html:99` + `faculty-dashboard.js:371` (`'mine'`/`'all'`, byte-identical lambdas); `report.html:196-203` (`'mine'` default/`'all'`); `admin.html:1960` (`'__all__'` = "All sections (entire offering)").

**Live-system risk:** Low-medium — `report.html` reads `?section=` and directors share those links.
Keep existing values accepted on read; change only what is written.

### FE-08 — Modals are Escape-dismissable but not screen-reader-announced or focus-trapped
**Severity:** Medium · **Category:** a11y
**Location:** 57 `classList.add/remove('open')` sites; `js/util.js:134` (`wireModalDismiss`, 27 callers)

**What:** Across every dialog: **1** `role="dialog"`, **0** `aria-modal="true"`, **0** focus traps,
**8** `.focus()` calls total. No dialog restores focus to its trigger on close.

**Why it matters:** `wireModalDismiss` is genuinely good — its header documents the drag-selection bug
that cost graders their typed feedback, and it handles Escape-closes-the-stack via
`topmostOpenModal()`. The *dismissal* semantics beat most hand-rolled dialogs. But a keyboard user
Tabbing inside an open dialog walks out into the page behind it, and a screen-reader user is never
told a dialog opened. **Federal-institution deployment, so Section 508 is live.**

**Confidence:** Confirmed.
**Fix:** `wireModalDismiss` is already the single choke point — extend it rather than touch 27 call
sites. On wire: `role="dialog"` + `aria-modal="true"` on the `.modal` child. On open: record
`document.activeElement`, focus the first focusable, install a `Tab`/`Shift+Tab` cycle bound to the
backdrop. On close: restore. ~25 lines in one function; `tests/app-schema/test-modals.mjs` already
exists to assert it.
**Live-system risk:** Low. Additive; existing mouse/Escape behaviour untouched.

### FE-11 — The open-coded modal dismiss in `lessons.html` drops the `mouseup` half of its own fix
**Severity:** Low · **Category:** duplication / correctness
**Location:** `site/faculty/lessons.html:1875-1896` (`promptSwapConfirm`); canonical `site/js/util.js:134-161`

**What:** The comment says *"Same both-ends-on-the-backdrop rule as every other dialog (util.js
wireModalDismiss), open-coded because this one is a one-shot promise."* The reason is sound — the
shared helper wires permanent listeners, this one must remove them when the promise settles. But the
copy tracks only `mousedown`:
```js
const onDown  = (e) => { downOnBackdrop = e.target === modal; };
const onClick = (e) => { const started = downOnBackdrop; downOnBackdrop = false;
                         if (e.target === modal && started) done(false); };
```
`util.js` records **both** ends because, as its header explains, `click` fires on the nearest common
ancestor. A gesture that *starts on the backdrop and releases inside the dialog* has
`e.target === modal` **and** `started === true`, and dismisses. `util.js` blocks that with
`upOnBackdrop`; this copy does not. It also has no Escape handling.

**Why it matters:** Small, and the failure direction is safe — it *cancels* a destructive action
rather than confirming one. But the dialog says *"N student reports will be PERMANENTLY DELETED"*, and
a mis-dismiss means the director re-opens the editor and does it again.

**Confidence:** Confirmed.
**Fix:** Add the `mouseup` listener to match, or — better — give `wireModalDismiss` an `opts.once` mode
returning a teardown, and delete the copy.
**Live-system risk:** Two-minute swap, faculty-only, no frozen URL.

## Positive findings

Patterns to **extend rather than replace**.

1. **`js/schema.js` is a genuinely good model layer.** SELECT strings and pure rules in one
   dependency-free file, with tests asserting the literal strings so a test proves what the browser
   sends. `pinnedQuestion()`'s role→text→position cascade, with its explicit refusal to fall back once
   roles are declared, is subtle correctness reasoning documented *at the line that implements it*.
   **The fix for FE-05 and FE-07 is "put more in here," not "restructure."**
2. **Comments explain the failure, not the code.** `util.js:114-133` (drag-selection dismissal),
   `hold-button.js:10-28` (`mouseleave` cancelling a 5-second hold), `schema.js:601-610` (flooring the
   release window, and why 2359 minus 7 days delivers six), `report.html:234-240`. Each names the
   reported symptom, the mechanism, and the date. This is the single reason the codebase is legible at
   26k lines, and why a dozen apparent smells could be ruled out as deliberate.
3. **`db-schema.js` is generated with a drift test.** The right answer to "PostgREST won't introspect
   for a publishable key," and it keeps 3571 lines out of the hand-maintained surface.
4. **`tests/app-schema/test-imports.mjs` is a linker for a project that has no linker.** It walks every
   module *and every inline page module*, extracts, parses, and resolves named imports against real
   exports. For a no-build-step site this is the highest-value test in the repo. **Extend it before
   adding any other kind of test.**
5. **Race conditions are handled properly where they were thought about.** `faculty-dashboard.js` uses
   a `MOUNT_GEN` counter re-checked after every await; `report.html` re-checks
   `reportInteraction !== interactionId` in all four async continuations. Generalize *this*.
6. **Deliberate divergence is justified in writing.** `faculty-gradebook.js`'s header explains why it
   does not reuse `loadFacultyDashboard` (payload) and explicitly retracts the correctness objection
   that used to also apply. That is how a duplicate should be documented.
7. **Zero loose equality across ~26k lines**, 3 `!important`, 911 `var(--token)` uses against 130 raw
   hex (nearly all `#fff` on a coloured background), 8 duplicated selectors in 1033.
8. **Theming is one mechanism, not per-component patches.** A single `[data-theme="dark"]` token block
   at `styles.css:90` plus a 5-line no-FOUC head snippet. `theme.js` writes through `prefs.js`;
   `auth.js:88-93` only re-applies when the server row actually disagreed with the local cache.
9. **`student-data.js` enforces the release window in exactly one place** and says why four renderers
   must not each do it. Verified. **This is the model the faculty side should copy.**
10. **`hold-button.js` was extracted specifically so it could be driven by a test** after shipping
    broken while inline in a 1500-line page. That is the argument for FE-04, already made and already
    acted on once.

### The single highest-payoff recommendation

**Extract the pure render functions out of the three big inline pages into their existing modules (#7).**

Items 1-3 are urgent and should ship this week — but they are point fixes. #4 is the biggest
*correctness* win. #7 is the biggest *handover* win, and the reason is arithmetic: today **9,293 of
22,238 hand-written JS lines (42%) sit inside HTML files**, unreachable by the 28-file test suite,
un-importable by any other page, and re-downloaded on every navigation. `admin.html` alone is 1908
inline lines against a 463-line module. A new maintainer told "the logic is in `site/js/`" will be
wrong about the three biggest pages in the product.

Everything else here gets easier once that ratio moves. The two duplicated modals (FE-06) and two
`openModal` copies exist *because* they are inline. The four scope vocabularies (FE-07) diverged
because each lives in a different HTML file. And the `effortPoints` divergence (FE-01) survived
migration 019's careful six-copy inventory for one reason: **it was inline, so it did not look like code**.

The project has already made this exact argument to itself, once, in `hold-button.js`'s header — a
control that shipped broken and stayed broken because *"left inline in a 1500-line page it was
untestable."* The fix is the same fix, applied to the rest of the site.

Critically, this needs **no build step and introduces none**: move a function into
`js/faculty-admin.js`, add `export`, add the name to the page's existing `import`. Do the pure
string-returning renderers first, and leave the `getElementById`/`addEventListener` wiring inline. No
frozen contract URL moves.
