PREP — test & mockup views

Everything under tests/. Nothing here is served to students or instructors, and none of it touches the live site. Serve the repo root with python -m http.server 8000 and open /tests/.

Design mockups — synthetic data, no back end

🧭 Navbar & brand explorationsNo sign-in Thirteen ways to make the top bar say what PREP is — "PREP Portal" with the acronym spelled out, the name stacked underneath or set beside the wordmark, the acronym picked out inside the full name, a badge, a hover reveal. Four of them (C–F) also carry iPREP, where the i is for interactive: defined alongside PREP in the footer, as a PREP/iPREP Portal wordmark, as a badge that lights up only inside an interactive lesson, and as an outright rename. Rendered as a system admin, with a light/dark toggle and a phone-width simulation. Fully standalone. 🗓️ Course calendar — six formatsDirector sign-in The term as a calendar rather than an ordered list, in six switchable formats over the same data — each makes one question cheap and the others expensive: Month for the week ahead, Term for the whole shape, Timeline for two lanes on one time axis where a lesson's M and T deadlines are joined by a diagonal whose slope is the gap, Agenda for a feed that never truncates a title, Pulse for the contribution-graph square-per-day with submission as fill, and Ledger for both dates side by side with a sortable spread column. A lesson has two deadlines — one per day track, each the evening before that track's own class — and the real gap runs one to four days. Per-section overrides on their own dates, the unpublished tail dashed, days off and term milestones, and SOC days flagged (afternoon sections start an hour early). Switch course to see the deadline hour move (215 is 1759, 110 is 2359). The day sequence is the real USAFA academic calendar; the courses on it are synthetic and no back end is touched. 🎨 Design sandboxesDirector sign-in The older preview pages — faculty dashboard, student dashboard, course/system admin, account & password flows, the lesson rollup, progress-bar styles. Gated by guard.js against live Supabase auth, so these need a director account.

Automated suites — command line, not browser pages

app-schema/ — Node test suites for the shipped ES modules and the app schema. Optional developer tooling; the site itself has no Node dependency. Run with node tests/app-schema/run.mjs.

browser-harness/ — headless-browser harness for UI that would otherwise go unverified. See its README.md.
